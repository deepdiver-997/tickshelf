# 合成 JSON 全链压测实测（2026-11-12）

## 结论

三轮、每轮七种有界负载，**21/21 PASS，共核对 13,608,000 条记录**。
另有小样本配置/协议冒烟，不计入这个压测总数。

本次数据全部来自外部工程的本地合成 JSON mock；没有使用真实 iFinD SDK、账号或行情。
测量覆盖生成 JSON → simdjson → TTAP → Redis → SQLite，四个 tickshelf 服务读取
同一份 INI 启动。参数与逐轮原始指标保存在
[`ifind-sim-results.json`](ifind-sim-results.json)；可复现方法及口径见
[`real-source-sim.md`](real-source-sim.md)。

**这不是单独的解析器吞吐，也不是 iFinD 服务能力或 tickshelf 的稳态饱和上限。**

## 环境与负载

- Apple M2 Pro，12 核，16 GiB 内存；系统实际报告 macOS 15.8.1 arm64。
- tickshelf 与桥均为 Release；Redis 8.10.3；Python 3.15.2。
- 每轮私有 loopback Redis、独立端口和数据库；Redis maxmemory=512 MiB、noeviction、无 Redis 磁盘持久化。
- flush=100ms，persister poll=100ms；evictor soft=128 MiB，只淘汰已持久化数据，紧急/在飞淘汰关闭。
- 固定种子=1；每批每证券一条，时间键用逻辑毫秒递增，接收时间用实际墙钟。
- 54 证券×2000批=108,000条；540×1000=540,000条；5400×200=1,080,000条。
- 各批不主动限速；不是模拟数据商真实的收费/QPS节奏。5400条一批拆成4096+1304两帧。
- 每轮配置相同，三轮顺序执行；开发机环境，无 CPU 绑核或文件缓存清空。

### 如何解读

1. **发送快不等于存得快。** 5400 证券经典模式可约85万条/s发送，但落库完成只有
   约10.4万条/s，停发后还需约9.1秒追平。将 SENT/发送用时称为“全链落库吞吐”会误导。
2. **该负载下写穿背压明显。** 第一轮5400证券单分片写穿中，桥 `send_ms` 累计约5.82秒，
   而源生成/解析分别约0.48/0.45秒。发送阶段耗时包含本地写入与等待，不能直接当成纯网络耗时；
   也没有 CPU profiling 足以进一步作精细归因。
3. **四分片有提升，但不是四倍。** 5400证券负载的完成吞吐中位数约24万条/s，是单分片
   的约1.66倍；三轮范围22.1–27.9万条/s，存在明显运行波动。这不是通用最优分片数结论。
4. **低基数轮次很短。** 54证券每轮仅约0.27–0.42秒即可全链完成，启动/flush相位占比大；
   5400证券约4.51–10.39秒完成。这些是有界突发结果，不是长期稳态压力验收。
5. **观测并非20ms精确钟。** 设定轮询20ms，但实际最大采样间隔达132.8ms，已在 JSON 中记录。
   可见时延含轮询、查询和调度开销；SQLite 查询可见不保证断电耐久。Redis内存也是采样峰值，
   不是进程RSS；所有轮次观测峰值不超过约134.1 MiB。
6. 未运行新的纯 TTAP `floodgen` 对照或全量 CPU/RSS profiling；不得用本表推算解析器极限，
   也不得直接与历史仅摄入吞吐比较。

## 正确性验收

每一轮均满足：

- 预期 = 合成 = 解析 = SENT = daemon ingested = 所有分片 SQLite 行数。
- 异常去重、CRC、重同步、flush 错误及最终未刷出记录均为零。
- 所有证券的记录数、首尾交易时间、证券集合和分片路由匹配。
- 首尾证券×首尾批次的价/量/标志与独立 Python 固定种子公式匹配。
- `queryd` 最新价响应 CRC/字段与 SQLite 样本一致。
- 每个自建 Redis、服务和桥均正常退出（退出码0），没有强杀冒充成功。

## 复现

按 `real-source-sim.md` 构建两个Release项目后，在 tickshelf 根目录：

```bash
# 每次自动分配新私有环境，输出原始日志/配置/数据库/采样明细目录
scripts/ifind_sim_drill.sh --suite stress
scripts/ifind_sim_drill.sh --suite stress
scripts/ifind_sim_drill.sh --suite stress

# 单独复现大基数四分片
scripts/ifind_sim_drill.sh --symbols 5400 --batches 200 --persist sqlite --shards 4

# 启动相关回归（不会接触默认Redis）
./build-release/tickshelf_tests --test-case-exclude='*redis-server*'
ctest --test-dir build-release -R '^startup_config$' --output-on-failure
python3 scripts/test_stack_runtime.py -v
```

库内 JSON 快照删去了个人绝对路径与临时端口，保留每轮计数、时间、样本字段、源阶段耗时、
服务最终计数和退出码。原始临时目录未自动删除，以便本机复查；不应把真实源数据沿用此流程公开上传。
